# CI gates

Every workflow under `.github/workflows/`, what failure it exists to catch, and
what a red run means. Rows are alphabetical so this drift check is a plain sort
comparison:

```bash
diff <(ls .github/workflows | sort) <(grep -oE '[a-z-]+\.yml' docs/ci-gates.md | sort -u)
```

Two kinds of red: a **merge block** (`ci.yml`, `malware-scan.yml`,
`vector-parity.yml` on a pull request) stops the change landing; a **production
signal** (the scheduled workflows) means `main` is already affected and no PR is
waiting on it. The same file can be both: a red PR run blocks the merge, a red
scheduled run does not.
